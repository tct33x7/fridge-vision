## E04 怎么做（计划，和老师确认后执行）

E02 的数字是在调规则的那批录像上测的，会偏乐观。E04 要回答"规则在**没见过的录像**上有多准"，所以顺序是：先冻结，再录，最后只打一次分。

1. **冻结**（E03 打完分、机位定下以后）：
   - 打一个 git 标签：`git tag e04-freeze-日期`；
   - 在 E04 记录开头写下冻结时的设置：提交号、用哪条路线（Mac / 板子代理 / 板子 NPU）、规则预设、计数线位置、排除名单、置信度门槛；
   - 再写下 5 个**自己预测的数字**（例如"门格的计数正确率 k/n"），打完分对照。
   - 冻结后到打完分之前，不改计数代码和参数，板子上的代码也不动。
2. **抽签生成动作清单**（45–60 个动作，分 3 段录，顺序随机）：
   `demos/yolo_web_counter/.venv/bin/python eval/make_action_list.py --out fridge_vision/runs/e04_overhead_日期 --sessions 3 --seed 抽签号`。
   分组和数量在 `eval/make_action_list.py` 的 `DEFAULT_SPEC` 里（可以换成自己家的东西）：搁板 12、门格 10、YOLO 不认识的东西 10、一手两样 4、快速 4、空开门 8、拿出又放回 4。
   第 4 步的"复杂情况"就是这里的几个分组。
3. **录**：固定机位、新版录制工具；每段打印对应的 `s?_动作清单.md` 照着做，做错的记在最后一列。
4. **第二个人盲标**：同学看 `propose_windows.py --plain` 出的拼图（不画框、不写系统结果），随机抽 20 个窗口独立记真值，和项目发起人的真值对比一致率。
5. **打一次分**：`eval/score_actions.py`，每个数字写成 k/n 并标明路线；每个失败归到"第一个出错的环节"（人眼看不清 / 检测器没框到 / 追踪断了 / 计数规则 / 开门检测），最大的那一类决定 11-21 的那一次改进。
6. 改进后的前后对比如果用的还是同一批 E04 录像，要写明"事后改的"。

## 约定

- **文件名**：`E编号_英文短名_日期.md`，例如 `E04_overhead_20261114.md`。
- **原始数据**：`fridge_vision/runs/e编号_短名_日期/`（录像、关键帧、`session.json`、`summary.md`、人工表），**永不进 git**。
  录制时加 `--out-dir` 指定，例如：

```bash
SOURCE=0 ~/Projects/bx-project/fridge_vision/run_record.command --trigger manual --out-dir runs/e03_overhead_20261114
```

- **每个记录写清**：目的、装置（相机、位置、触发、参数）、过程、结果（附命令，能重跑）、真值质量、观察、局限、对设计的影响。
- **谁写的要分清**：脚本算出的数字、Claude 的观察、你的观察分开写。你的观察那一节只由你写。
- 报告要用的图挑好、确认没有人脸后，放进 [docs/report/figures/](../report/)。
