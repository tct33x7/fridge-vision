# E02 · 光线、抖动优化：过线计数逻辑（2026-11-08）

7 步待办流程的第 2 步。对象是 `demos/yolo_web_counter`（YOLO11s + ByteTrack + 拖线计数）。
数字全部来自脚本 `replay.py`，命令见最后一节。"你的观察"一节留给你写。

## 目的

第 1 步的 demo 有一个明显问题：物品在计数线附近晃几下，就会 +1 −1 +1 −1 地乱计。这一步要：

1. 做一个**能重放**的测试办法：同一段视频，旧逻辑和新逻辑各算一遍，用数字比较多计、漏计、类别跳变；
2. 针对抖动和光线改计数逻辑，每一项改动都用重放结果说明有没有用。

## 装置

| 项 | 值 |
| --- | --- |
| 检测 / 追踪 | YOLO11s（COCO 80 类）+ ByteTrack，置信度 0.35，输入 640，Mac MPS，约 27–30 ms/帧 |
| 计数线 | 画面正中竖线 `[0.5, 0, 0.5, 1]`；从右往左过线 = 放入（+1） |
| 旧逻辑 `baseline` | 第 1 步原版：物体中心离线超过 6 像素就算到了另一侧，换边就计数 |
| 新逻辑 `default` | 见下文"改了什么" |
| 测试视频 A | **合成视频**（`tools/make_test_video.py`，3 个随机种子各一段，每段 42.8 秒、18 个片段、真值 14 次进出） |
| 测试视频 B | **桌面实拍**（`tools/record.py`，外接相机）：**待录**，见"下一步" |
| 数据 | `demos/yolo_web_counter/test_videos/`（视频、真值、检测缓存）。**不进 git** |

合成视频是把 ultralytics 自带示例图里的**公交车**和**领带**贴到背景上，按剧本移动，并加上手抖、运动模糊、光线变化、遮挡。
选这两样东西只是因为 YOLO 认得出来，和冰箱无关。它考的是"过线计数"这一步，**不能代替真实录像**。

18 个片段（两轮，每轮 9 种）：正常进入、正常拿出、在线上晃 2 秒后进入、伸过线又缩回（不算）、快速穿过（带模糊）、过线时光线一明一暗、过线时被挡住 12 帧、暗光下进入、离线远处来回晃（不算）。

**计分**：按片段算。片段里方向和类别都对的事件算"计对"；片段里多出来的事件，或者类别错了，算"多计"；该有却没有的算"漏计"。

## 原因（看追踪数据发现的）

1. **滞回太窄**：6 像素比手抖还小，物体中心在线附近晃一下就算换边。
2. **ByteTrack 换编号**：物体在线附近停留、晃动时，追踪器会不停地给它换新编号。一个片段里观察到 266 → 270 → 269 → 274 → 283 连换 5 个。新编号不知道物体是从哪一边来的，换编号之后的过线就漏计了。
3. **类别跳变**：同一个物体有几帧被认成相近的类（实测出现过 bus → truck、bus → tv）。旧逻辑用"过线那一帧"的类别，碰上认错的那一帧就记错。

## 改了什么（`counter.py`，`PRESETS["default"]`）

| 改动 | 参数 | 做法 |
| --- | --- | --- |
| 滞回带随物体变宽 | `hysteresis_box=0.5` | 物体中心要越过线 **6 像素 + 半个框宽**，也就是整个框都过了线，才算到了另一侧 |
| 丢失后续接 | `relink_frames=20`、`relink_dist=1.5` | 新编号出现时，如果 20 帧内附近刚丢失过一条轨迹，就接上它，继承"从哪边来"和类别票。有几条候选时接看到得最久的那条，类别不要求一样 |
| 类别投票 | `class_vote=True` | 计数时用整条轨迹按置信度加权投票选出的类别，而不是当前这一帧的类别 |
| 中心点平滑 | `smooth_alpha=0.5` | 中心点做指数平滑 |
| 最短轨迹 | `min_frames=3` | 轨迹至少被看到 3 帧才允许计数 |
| 冷却 | `cooldown_frames=15` | 同一个物体计数之后 15 帧（0.5 秒）内不再计数；冷却期间的换边会等稳定之后再判断 |
| 软件亮度处理 | `--light gain/clahe` | 可选，默认关闭（理由见结果 3） |
| 锁定曝光 | `--lock-exposure`、`--exposure` | 可选，调用 OpenCV 关闭自动曝光。Mac 上大多不支持；**还没在任何相机上验证过** |

## 结果

### 1. 前后对比（合成视频，3 个种子，`--light off`）

| 视频 | 应有 | 旧逻辑：事件 / 多计 / 漏计 | 新逻辑：事件 / 多计 / 漏计 |
| --- | --- | --- | --- |
| 种子 1 | 14 | 29 / **17** / **2** | 13 / **0** / **1** |
| 种子 2 | 14 | 26 / **15** / **3** | 13 / **0** / **1** |
| 种子 3 | 14 | 27 / **16** / **3** | 13 / **0** / **1** |
| 合计 | 42 | 82 / **48** / **8** | 39 / **0** / **3** |

新逻辑剩下的 3 次漏计都是"快速穿过"片段：YOLO 在那 12 帧里一个框都没有检测到，计数逻辑没有东西可以算。

种子 1 逐片段（✓ = 这个片段完全正确）：

| 片段 | 旧逻辑 | 新逻辑 |
| --- | --- | --- |
| 线上晃动后进入（两轮） | ✗ 9 次 / 6 次乱计 | ✓ ✓ |
| 伸过线又缩回（两轮） | ✗ ✗ 各多计 2 次 | ✓ ✓ |
| 过线时被挡住（两轮） | ✓ / ✗ 漏计 | ✓ ✓ |
| 快速穿过（两轮） | ✓ / ✗ 漏计 | ✓ / ✗ 漏计（没检测到） |
| 其余 10 个片段 | 全对 | 全对 |

### 2. 每项改动各起多大作用（种子 1）

两种看法：在旧逻辑上**只打开**一项；在新逻辑上**只关掉**一项。

| 改动 | 旧逻辑只开这一项：多计 / 漏计 | 新逻辑只关这一项：多计 / 漏计 |
| --- | --- | --- |
| （不改动） | 17 / 2 | 0 / 1 |
| 滞回带随物体变宽 | 0 / 4 | 9 / 1 |
| 丢失后续接 | 19 / 1 | 0 / 4 |
| 中心点平滑 | 13 / 2 | 0 / 1 |
| 冷却 | 13 / 2 | 0 / 1 |
| 最短轨迹 | 17 / 2 | 0 / 1 |
| 类别投票 | 17 / 2 | 0 / 1 |

从表里能读出：

- **滞回带**消掉了几乎所有多计，但单独用会多漏 2 次：换编号后，新轨迹是从"线上"开始的，不知道自己从哪一边来。
- **丢失后续接**单独用没有帮助（还多计了 2 次），但和滞回带一起用，就把那几次漏计补回来了。这两项要一起用。
- **平滑、冷却**单独用各少多计 4 次，但加上前两项之后就看不出作用了。**最短轨迹**在这几段视频里没有起过作用。这三项先保留下来做保险，等真实录像再看。
- **类别投票**在这段视频里看不出作用，因为原始检测里类别跳变是 0 次。所以又做了下面的压力测试。

### 3. 类别跳变压力测试（种子 1，`--class-noise 0.2`）

在缓存好的检测结果里，随机把 20% 的框换成相近类别（bus↔truck、tie↔umbrella，对应真实场景里的 bottle↔cup），一共造成 255 次类别跳变。这是**模拟出来的**，不是真实检测。

| 方案 | 计对 | 多计 | 漏计 |
| --- | --- | --- | --- |
| 旧逻辑 | 8 | 21 | 6 |
| 旧逻辑 + 只开类别投票 | 12 | 17 | 2 |
| 新逻辑 | 13 | 0 | 1 |
| 新逻辑 − 关掉类别投票 | 8 | 5 | 6 |

关掉投票，新逻辑会错 5 次；打开投票，一次类别错都没有。

### 4. 光线

| 方案（新逻辑） | 种子 1：多计 / 漏计 | 种子 2 | 种子 3 | 每帧耗时 |
| --- | --- | --- | --- | --- |
| `off` 不处理 | 0 / 1 | 0 / 1 | 0 / 1 | 27–30 ms |
| `gain` 拉平整体亮度 | 0 / 1 | 1 / 1 | 0 / 1 | 28–31 ms |
| `clahe` 局部均衡 | 2 / 3 | 1 / 2 | 0 / 1 | 约 38 ms |

在合成视频上，两种软件亮度处理都**没有带来改善**。CLAHE 还会更慢，而且追踪编号更多（37–40 个，不处理时是 26–31 个），所以默认关闭。
合成视频里，亮度 0.2 倍的"暗光"和一明一暗的"闪烁"，YOLO 本来就能检测到，这一项可能是合成视频太简单。**要看你录的 light1 才能下结论。**

锁定曝光要在真实相机上才能测。Mac 用的 AVFoundation 后端一般不让 OpenCV 改曝光；OrangePi（Linux V4L2）通常可以。放到第 6 步验证。

## 真值质量

合成视频的真值由剧本生成，是精确的。片段的起止帧写在 `*.truth.json` 里，计数事件允许比片段结束晚 10 帧。

## 观察（Claude）

- 多计几乎全部来自"在线附近停留"：晃动、犹豫、伸过去又缩回。物体快速、干脆地过线时，旧逻辑也是对的。
- 漏计的主要来源是追踪换编号，而不是检测不到。新逻辑剩下的漏计是真的检测不到，计数逻辑解决不了，只能靠更好的检测（更低的置信度阈值、更高的帧率、少一些运动模糊）。
- 网页 demo 换成新逻辑后，播放同一段合成视频（`--source` 视频文件），得到的结果和 `replay.py` 一样（13 次事件）。
