# E01 · 正面机位基线（2026-11-07 晚）

第一次在真冰箱上测量。数字来自脚本；"观察"一节是 Claude 看关键帧得到的；"你的观察"留给你写。

## 目的

在写识别代码之前，先测四件事：开门触发靠不靠得住、东西拍不拍得到、YOLO 能认出多少、类别无关的过线 + 光流方向这条路行不行（[PROPOSAL §4](../PROPOSAL.md)）。

## 装置

| 项 | 值 |
| --- | --- |
| 相机 | UGREEN UVC 1080p 有线定焦，OpenCV 编号 0，录像 15 fps |
| 位置 | Mac 放在厨房对面台面，**正对冰箱**（距离没量）；嵌入式冰箱，门轴在右，门向右开，门内侧有四五层门格 |
| 触发 | 先试自动（画面亮度），失败后改**手动**（开门前、关门后各按一次 `o`） |
| 过线带 | `--line 0.55 --band 0.50`，覆盖冰箱开口和打开的门；前 3 次空开门用的是 `0.43 / 0.26` |
| 真值 | 每次关门后在终端里打"放入 / 拿出 / 备注" |
| 数据 | `fridge_vision/runs/e01_front_20261107/`（16 个会话、`summary.md`、`人工可见性.md`、`_test_sessions/` 测试会话）。**不进 git** |

## 过程

1. 19:50–20:14 调试：两段录到的是自带相机（对着人），已移到 `_test_sessions/`；两次自动触发都在开门后 1–7 秒被误判成"关门"（亮度回落）。
2. 第一轮手动录制一次都没录上：按 `o` 的代码有 bug，开关门都察觉不到。修复见提交 a45bd94。
3. 20:26–20:49 正式录 16 次：空开门 3 次，有物品 13 次（只放入 7、只拿出 4、又放又拿 2）。其中 2 次和计划不一样（备注写了"忘了放 / 忘了拿"），所以多录了 2 次；真值照实记了，都有效。
4. 21:35 按你的备注和口述修正真值（见下文"真值质量"）。

## 真值质量

13 次有物品的会话里，**3 次的真值要事后修正**：一次把"拿出"写成了"放入"，一次在"放入"里多打了 `nothin`，一次把可乐拼错。
另外，全部名字从英文改成了家里的中文叫法，蓝莓按"一盒"计 1。原始输入保存在每个 `session.json` 的 `truth_original` 里。

这说明**真值本身也有错误率**，大约 3/13。以后最好在网页上从家庭词表里点选真值，不要在终端里手打（[ARCHITECTURE §9](../ARCHITECTURE.md)）。

## 观察（Claude 看关键帧）

1. 人一站到冰箱前，**背就挡住了冰箱内部**和放东西的那一下；关键帧大多是背影。
2. 东西最清楚的时刻常常是**走过来时拿在手里**，而不是放进去的那一下。
3. 门内侧有四五层门格，**饮料瓶基本都放在门格里**；真值 27 件里 12 件是瓶装饮料（乌龙茶 5、可乐 5、依云 2）。
4. 前后几次会话的光线明显不同，有的很暗。

## 局限

只有一位测试者、25 分钟、按脚本做的多、正面一个机位、手动触发；前 3 次和后 13 次的过线带不同。这些数字只能说明正面机位的问题，不能代表门洞上方机位。

## 对设计的影响（→ 11-08 决定）

- 相机离开正面，改到门洞上方（[DECISIONS 11-08](../DECISIONS.md)，[ARCHITECTURE §3](../ARCHITECTURE.md)）。
- YOLO 不当守门员；亮度触发不可靠，倾向门磁。
- 新机位要专门检查**门格**能不能拍到（观察 3）。
- 真值改为点选录入（真值质量）。

## 这批数据还能怎么用

1. 它是 11-08 改机位的**依据**：正面机位的问题有数字支撑，不是凭感觉改的。
2. 它是**对照组**：E02 / E03 用同一套脚本，结果和这里并排比较。
3. 填完人工表能得到两个数：正面机位的人眼可见率，以及门格动作的占比。后者直接决定新机位怎么装。
4. 家庭词表的第一批 10 个名字。
5. 拿到密钥后，先用这批关键帧把大模型认名流程跑通（不代表新机位的准确率）。
