## 2. 系统现在长什么样

```text
UGREEN USB 相机（640×480，15 帧/秒）
        │ 每一帧
        ▼
OrangePi 4 Pro · smart_fridge_demo（FastAPI :8080，systemd 开机自启）
  ├─ 开门检测 door_watcher.py：待机时每秒看 5 张小图，画面变化 > 3% 或亮度跳变 > 18（连续 2 次）→ 唤醒
  ├─ 识别引擎（老师 17:04 接入）：NPU YOLOv5s（yolov5.nb，640 输入）+ 轻量 ByteTrack；CPU yolo11s 兜底
  ├─ 过线计数 line_counter.py（第 2 步规则）：整框过线、确认 3 秒、丢失续接、类别投票、冷却
  ├─ 过滤：人和 61 类不会放进冰箱的东西不计；静止物品不显示（老师 17:19）
  ├─ 静止 6 秒 → 待机；一次开门 = 一个"会话"（开始、时长、计数、唤醒 / 待机原因）
  ├─ SQLite：counter_events（计数流水）；库存、扫描记录在另外的表
  └─ 网页：首页"计数"区（实时画面、待机 / 识别中、净计数、最近进出、上次开门概况）；原有拍照识别、库存等页面
        │
        ▼
手机 / 电脑浏览器（同一 WiFi：http://192.168.3.167:8080）；板子桌面开机自动打开 Firefox
```

- 识别和计数只在"开门"时运行；计数和手动拍照共用一个摄像头，进"摄像头"页面会暂停计数。
- 开发在 Mac 上，代码在仓库 [`orangepi_app/`](../../orangepi_app/)，用 [`deploy/opi.sh`](../../deploy/opi.sh) 同步到板子。

## 4. 每一步的细节

### 第 1 步 · 电脑端初步进出统计（完成）
- [`demos/yolo_web_counter/`](../../demos/yolo_web_counter/)：FastAPI + 网页，选摄像头、在画面上拖计数线、翻转方向、调置信度；YOLO11s（COCO 80 类）+ ByteTrack；Mac（Apple 芯片）约 30 帧/秒。
- 老师写的，11-08 11:41 进入仓库。

### 第 2 步 · 光线、抖动优化（已合并；补充在分支上）
- 计数规则（[`counter.py`](../../demos/yolo_web_counter/counter.py)，预设 `baseline` / `default` / `hidden`）：
  整个框过线才算换边、丢失后续接（20 帧内、2 倍框对角线内）、类别按整条轨迹投票并可事后改正、计数后冷却、中心平滑、最短 3 帧、**确认时间 3 秒**（拿出又马上放回、在线上晃都不计，"只看最后"）。
- 重放工具 `replay.py`：同一份检测结果上比较新旧规则；测试录像在本机 `demos/yolo_web_counter/test_videos/`（不进 git）。
- 结果（[E02](../experiments/E02_light_jitter_20261108.md)）：3 段桌面实拍（11 次真实进出）多计 12 → 0、漏计 5 → 2；3 段合成视频（42 次）多计 48 → 0、漏计 8 → 3。软件调亮度没有改善。
- "看不到冰箱里面"（门洞上方机位）的模拟：把画面里侧涂黑后，`default` 明显变差；新增 `hidden` 预设（里侧只露 10% 时计对 3 → 7 次），只在门洞上方机位用。
- **补充（分支 `step2c-trackers`，未合并）**：比较 ByteTrack / OC-SORT / BoT-SORT / Deep OC-SORT，并新增"物体光流"补救快速移动：桌面漏计 2 → 1、合成 3 → 2，没有新增多计；更正了 E02 里"YOLO 没检测到"的说法（其实是追踪器没连上）。记录在该分支的 E02b。在单独的工作文件夹 `~/Projects/bx-project-trackers` 里。

### 第 3 步 · 待机、自启动（第一版已部署）
- 没有门磁，只能看画面（[`door_watcher.py`](../../orangepi_app/app/services/door_watcher.py)）：
  - **待机**：不跑识别；每秒看 5 张缩到 160 像素宽的灰度图，和"背景"比。比较前扣掉整幅画面的平均亮度差，自动曝光、光线慢变不算动。
  - **唤醒**：变化像素 > 3% 或平均亮度差 > 18，连续 2 次（约 0.4 秒）。
  - **待机**：前后两帧变化 < 1% 持续 6 秒，或一次识别超过 300 秒；休眠时把还在等确认的过线算完，静止的新画面当新背景。
  - 摄像头刚打开的头 2 秒等曝光稳定、只学背景。只看"画面动不动"，不看"识别到几个东西"（台面上的瓶子会一直被识别到）。
- 每次开门记一个会话，网页、状态接口、日志（`[door]`）都能看到。**计数 0 个的会话 = 误唤醒**，用来调参。
- 摄像头连续约 3 秒读不到画面（拔插）会自动重新打开；之前这种情况会一直卡住。
- 8 个参数都在板子 `.env` 里（`SMART_FRIDGE_DOOR_*`），不写用默认值，说明见 [ORANGEPI.md](../../orangepi_app/ORANGEPI.md)。
- 开机自启：沿用老师配好的 systemd `smart-fridge.service`（root、失败自动重启、桌面自动打开网页）。
- 第一版**有意没做**：预录缓冲（醒来前那一小段不补识别）、门磁输入、按区域区分"门"和"人"。

### 第 6 步 · 部署到 OrangePi 并与主功能合并（进行中）
- 已完成：计数作为主程序的一部分在板子上运行（首页计数区）；识别走 NPU；管理脚本、备份、部署版本记录。
- 没完成：**计数事件 → 库存**（放入建批次、取出扣减），现在计数只写 `counter_events`；库存初始化（拍照录入）；手机上的"对 / 错 / 改"。

### 第 4、5、7 步（未开始）
- 第 4 步要测：一手拿两样、两手各一样、伸进去又拿回来、快速进出、袋装、YOLO 不认识的东西（蓝莓、萝卜干酸菜、辣椒酱这类）。
- 第 5 步：同是 bottle 的饮料（乌龙茶、可乐、依云）靠 OCR 区分；板子上已有 OCR 流水线（`ocr_*.py`，RapidOCR）。
- 第 7 步：先用手机试机位（实验 E03），再装相机、按 E01 的真值协议测（E04），和 E01 并排对比。
