版本 4.0　|　2026-11-08　|　仓库 `~/Projects/bx-project`，私有 GitHub `tct33x7/fridge-vision`　|　架构细节见 [ARCHITECTURE.md](ARCHITECTURE.md)

4.0 把相机改到冰箱门洞上方，只拍手和手里的东西；库存由用户初始化，之后靠进出事件增减；当前先跑通"往哪走、手里是什么"的识别，11-22 可交付。

## 0. 这一版改了什么

| 方面 | 3.0（11-07） | 4.0（11-08） | 原因 |
| --- | --- | --- | --- |
| 相机位置 | 临时放在厨房对面台面，正对冰箱 | **门洞上方朝下**，只拍手和手里的东西 | 实验 E01：人站在冰箱前时背挡住冰箱和手；空开门 3/3 被切出"动作" |
| 库存 | 只靠进出事件 | **初始化**（手动输入或拍照）+ 进出事件 + 纠错 + 每周对账 | 门口相机看不到冰箱里原有的东西 |
| 开门触发 | 画面亮度 | 倾向**门磁**，画面法兜底 | E01：自动曝光 1–7 秒内把亮度拉回，两次都误判关门 |
| 识别架构 | 待 11-08 拍板 | **类别无关过线 + 大模型认手里的东西**；YOLO 只做辅助 | E01：YOLO 召回 2/27，只认出苹果 |
| 主机 | Mac 唯一主机 | **OrangePi 4 Pro**；Mac 做开发机 | 手头已有；有 GPIO 接门磁；不需要实时识别 |
| 界面 | 手机网页 | 同一套网页：手机先，门边小屏可选 | 后端本来就为触摸屏 + 手机设计 |
| 当前重点 | 测量 | 先跑通门口识别：**方向 + 手里是什么** | 11-08 与老师讨论定 |

不变：把难点做好、不做全；先测量后设计；人在回路；11-22 可交付，11-29 打磨。

## 1. 项目一句话

在冰箱门洞上方装一个摄像头，开门时自动记录放进去、拿出来的食材，不用扫码、不用拍照；并且能**用数字说明自己有多准**。

**为什么值得做**。家里冰箱放了什么没人记得清，剩菜过期、重复买是常事。前身项目"饮食均衡助手"做了手机拍照识别和扫码枪，技术上能用，但要用户多做一步，于是没人用。所以这一期把交互压到零：开门即记账，认错了在手机上一键纠正。

## 2. 要做好的难点

在真实厨房的光线和动作下，可靠地判断"手里拿着什么、往哪个方向过了门洞"，并且能度量自己的准确率。认名交给大模型，库存后端是现成的，这两样不是重点，也不必假装是。

方案是怎么一步步变过来的（拍照扫码 → 纯视觉过线 → 盲审 → 真冰箱测量 → 门洞上方机位），见 [DECISIONS.md](DECISIONS.md) 和 [experiments/](experiments/)。代码和文档有 AI 助手参与，分工见仓库首页"协作与 AI 使用"。

## 3. 系统设计（4.0）

```text
门磁（GPIO）/ 画面触发 + 门洞上方 USB 相机
   │ 开门：环形缓冲 1–2 秒 + 整段录像 + 过线关键帧 + session.json
   ▼
离线分析（关门后十几秒内，不要求实时；可失败、可重试）
   ├─ 切动作：门洞截面上的运动段，和类别无关
   ├─ 判方向：截面两侧的光流 → 往里 / 往外
   ├─ 配往返：伸进去一腿 + 拿出来一腿
   ├─ 看手里：每一腿手里有没有东西、是什么（大模型 + 家庭词表）
   └─ 事件：放入 / 拿出 · 名字 · 数量 · 置信度 · 证据图
   │ HTTP
   ▼
库存后端 smart_fridge_app（现成：商品 · 批次 · 流水 · 撤销 · 拍照录入 · 备份，34 个测试）
   初始化库存 · 事件改库存 · 待确认队列 · 纠错 · 每周对账 · 保质期
   │ 同一套网页
   ▼
手机浏览器（家里局域网）+ 门边小屏（可选）："刚才的变化"按会话分组，每条带图，一键 对 / 错 / 改
   │ 纠错
   ├─ 每天纠错次数、库存对账准确率（使用期指标）
   ├─ 家庭认名记忆：纠正过的 (图, 名字) 做示例喂给大模型，下次认得
   └─ 回放评测集：同一批录像上重跑新算法，前后对比
```

**和 3.0 的三处不同**：相机从正面挪到门洞上方，人基本不进画面；库存不再只靠事件，而是"初始化 + 事件 + 对账"；采集、分析、后端三个进程在 Mac 上开发、在 OrangePi 上运行。`door_demo.py`（检测 + 追踪 + 实时过线）保留为对照组，不再开发。机位要提前想到的七个问题（门格在开口外面、俯视只看到瓶盖、景深、画面方向、曝光、冷冻抽屉、安装）见 [ARCHITECTURE.md §3](ARCHITECTURE.md)。

**设计原则**

- 没有数字不改架构；每个改动都在同一批录像上前后对比。
- 为长尾设计：家里常买的东西不在任何类别表里，名字由大模型给、由人纠正。
- 人在回路：自动记账 + 一键纠错，纠错本身就是数据。
- 隐私分级：门洞上方的相机基本拍不到脸；研发期录像只留在本机；产品期只留关键帧并定期清理；大模型只收关键帧（最好只收手附近的裁图）；对外展示只用无人脸的帧。
- 同一套代码：Mac 上开发，OrangePi 上运行，换主机只是复制目录。

## 4. 评测方法（本版核心）

真值协议：录制脚本在每次关门后在终端里问"放入了什么 / 拿出了什么"，照实打；什么都没拿也要记（直接回车），它是误动作的负样本；刻意补的"练习轮"备注写"练习"。每次测量记成一个实验（[docs/experiments/](experiments/)），原始数据放 `runs/<实验>/`，是私有评测集，不进 GitHub。真值本身也会错：E01 的 13 次有物品会话里 3 次要事后修正，以后改在网页上从家庭词表点选，修正留记录。

| 指标 | 定义 | 工具 | 决定什么 |
| --- | --- | --- | --- |
| 触发可靠性 | 可疑误触发（< 2 秒的会话）、超时强制关门（疑似厨房灯）、漏触发（人工记） | `analyze_sessions.py` | 亮度法够不够，要不要门磁 |
| 人眼可见率 | 看录像，人眼能认出手里东西的比例（按件）；顺带记东西放在搁板还是门格 | 人工表 | 机位和角度；人眼看不清的，模型也认不出 |
| 可见率（脚本口径） | 有"放入"真值的会话里，拍到至少 1 张关键帧的比例 | `analyze_sessions.py` | 只说明过线带里有东西在动，要和人眼可见率一起看 |
| YOLO 召回 | 真值物品被 YOLO 在该会话里看到过的比例 | `analyze_sessions.py` | YOLO 能不能当守门员（E01：不能） |
| 认名召回 / 精确率 | 真值物品被大模型叫出来过的比例；大模型给的名字对得上真值的比例；失败按 看不清 / 遮挡 / 不在画面 / 认错 分类 | `name_keyframes.py` | 大模型认名可不可靠，失败主因是什么 |
| 动作检出 / 次数一致 / 方向一致 | 有真值的会话里检出 ≥ 1 次伸手的比例；伸手次数等于真值件数的比例；单向会话里方向全对的比例；空开门却有动作的会话数 | `process_session.py` | 类别无关过线 + 光流方向这条路行不行 |
| 每天纠错次数 | 真实使用期，家人每天在手机上点"错 / 改"的次数 | 后端统计（11-16 起） | 系统到底好不好用；改进前后对比 |
| 库存对账准确率 | 每周对照冰箱实物核对系统库存，对得上的比例 | 人工对账 + 后端 | 账会不会慢慢错；对用户最诚实的数字 |

目标不是一次达标，而是每个数字都有来源、有趋势。盲审对 2.2 的批评正是"没有任何一条测量路径"；3.0 起把测量放在写识别代码之前，4.0 的新机位就是测量推翻旧设计的第一个结果。各实验的数字见 [docs/experiments/](experiments/)。

## 5. 功能范围

**做**

1. 门洞上方采集：门磁（或画面）触发、环形缓冲、整段录制、过线关键帧、真值录入（录制工具 11-07 已完成；门磁、横线方向待做）
2. 关门后离线识别：穿越 → 方向 → 往返 → 手里有什么（大模型 + 家庭词表）→ 事件 → 入库
3. 库存：初始化（手动输入或拍照，复用后端的拍照录入）、事件增减、待确认队列、每周对账、按类别保质期与临期提醒；"拿出"先进待确认，可靠后再自动扣减
4. 手机网页"刚才的变化"：按会话分组、带证据图、一键 对 / 错 / 改；门边小屏用同一套网页（可选）
5. 评测：会话统计、认名评测、离线链路、回放对比、人工可见性表；E01 / E03 对比表
6. 报告、2 分钟视频、失败图集（11-22）

**不做（除非老师要求）**

- 模型微调；冷冻抽屉；N100
- 原生 App、微信小程序；公网访问、多用户、云同步
- 条码、小票、包装日期 OCR；实时货架盘点；扫码枪硬件

## 6. 新构思（按性价比排序）

1. **家庭认名记忆**。每次在手机上纠正一个名字，就把 (证据图, 正确名字) 存起来；下次调大模型时把最近的几个例子一起发过去："在这个家，这种红杯子叫 Tims 咖啡"。不用微调就能"学会"这个家的东西，而且效果可以用认名精确率的前后对比来证明。这是最适合写进报告的改进。
2. **先用手机试机位**（4.0 新增）。装支架之前，把手机临时固定在 2–3 个候选位置，各录 10 次，按人眼能认出的次数选机位。半小时，成本为零，又是一次"先测量再动手"。
3. **每周对账**（4.0 新增）。对照冰箱实物核对系统库存，得到库存对账准确率；它能发现慢慢累积的错账，是对用户最诚实的数字。
4. **按"腿"投票**。一次伸手有多张关键帧，大模型逐帧判断手里的东西后按置信度加权投票，比单帧稳。`name_keyframes.py` 已输出逐帧结果，投票在 `process_session.py` 里做。
5. **门磁**（4.0 起倾向采用）。一个几块钱的干簧管门磁接 OrangePi 的 GPIO，旧项目的 `camera_system` 已有读 GPIO 的代码；"纯视觉"指的是不要用户动手，不是禁止一个传感器。
6. **回放评测**。所有录像落盘，任何算法改动都在同一批会话上重跑，出一张"改动前 / 后"表。这是让"我改进了"变成可证明的句子的唯一办法。
7. **失败图集**。每类失败（看不清、遮挡、不在画面、认错、误触发）各挑一张图，配一句原因。报告里最有说服力的素材。
8. **隐私分级**（见 §3 原则）。门洞上方基本拍不到脸；大模型只收关键帧，最好只收手附近的裁图；可以说明将来换成本地小视觉语言模型的路径。
9. **相机支架自己设计、3D 打印**（4.0 新增）。沿用旧项目扫码枪外壳的建模流程，自己设计、自己打印，每一版拍照留档。
10. **食物浪费统计**（可选，11-28/29）。按批次统计"到期未用"的次数，把项目的意义从"记账"提到"减少浪费"。

## 8. 数据与接口

**磁盘上的会话**（研发期真值与评测集）：`runs/<实验>/<会话>/`（例如 `runs/e01_front_20261107/`）含 `clip.mp4`、`kf_NN_<t>s.jpg`、`session.json`（触发原因、关门原因、时长、关键帧、运动轨迹、YOLO 检测、真值），以及工具生成的 `naming.json`（逐帧认名）、`events.json`（穿越 / 伸手 / 事件）、`contact.jpg`。

**待改**（盲审指出、已核对属实；4.0 定了，按顺序改）：

- 大模型给的名字要真正用作 `label_zh` 和商品名，现在只躺在 `vlm_json` 里
- 改名后类别和保质期要按新名字算，现在仍按原英文标签
- `status` 加 `confirmed` / `wrong` 和修正后的名字，否则准确率永远测不出来
- 证据图 `ON DELETE RESTRICT` 与"定期清理"冲突，清理时要先解除引用
- "拿出"自动扣减先隐藏；类别表按常买清单重做

## 10. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 门格在开口外面，往门格放东西拍不到 | 先量占比（E01 人工表"放在哪"一列）；机位选能同时看到开口和门内侧的角度，或给门格单独划一块区域 |
| 俯视只看到瓶盖；近处糊、远处小 | 相机朝屋里斜 20–30°；广角、1080p、≥ 30 fps；用走近时的帧 |
| 代码还不支持横线方向（门洞上方机位必需） | 先改代码，改动不大；临时把相机转 90° 装 |
| 开门触发不可靠 | 门磁；画面法 + Linux 锁曝光兜底；手动 `o` 应急 |
| OrangePi 装机吃掉太多时间 | 识别先在 Mac 上跑通；装机按 `deploy/` 清单、和老师一起；来不及就用 Mac 当主机交付 |
| 拿不到 API 密钥 | 用 `--fake` 跑通流程；认名评测顺延，密钥不是架构前提 |
| 大模型认错或编名字 | 精确率单独算；拿不准就进待确认；家庭认名记忆改善 |
| "放入 / 拿出"方向判错 | 方向一致率单独算；判不准时只记"经过"不记方向，由人补 |
| 库存慢慢错账 | 待确认队列 + 每周对账；对账准确率单独算 |
| 真值本身有错 | 网页点选录入；修正留记录（`truth_original`） |
| 周中没时间 | 周中只跑录制，不改代码 |
| 隐私：关键帧发给大模型服务商 | 门洞上方基本拍不到脸；只发关键帧，最好只发手附近；家人知情；报告写明；将来可换本地模型 |
