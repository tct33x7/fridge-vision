# 家用纯视觉冰箱记账系统 · 项目计划书

版本 2.1　|　2026-11-06（主机改为 N100）　|　仓库 `~/Projects/bx-project`
在线可分享版本（含架构图与时间线，可导出 Word / PDF）：https://claude.ai/artifact/5FRAXpgANS4yXgAqxmwiwy

## 1. 项目概述

在冰箱门口装一个摄像头，开门时自动认出手里放进去、拿出来的食材并记账；两周内在家里跑通，之后换成一台 N100 迷你主机独立常开运行。

**背景**。项目前身"饮食均衡助手"已有两套可运行软件（手机上传识别 demo、本地优先库存后端）和一把扫码枪壳体，但都要求用户主动拍照或扫码。实际使用里"多一步"就会不用，所以本期把交互压到零：开门即记账。

**目标**

1. 第一步：Mac 摄像头桌面闭环，手持物品过线 10 次至少 8 次判对。
2. 第二步：无线摄像头贴到真冰箱上、系统仍在 Mac，真实使用 3 天，差分正确率不低于 70%。
3. 第三步：N100 迷你主机替代 Mac，断电重启 1 分钟内自动恢复。

**完成标准**：真实冰箱连续用两周，每天的进出记录看一眼就能认可，人工纠错每天不超过 2 次。

## 2. 用户与场景

使用者是家里所有人，照常开冰箱放东西，不需要学习；查看者主要是买菜和做饭的人，用手机打开家里局域网的网页。

| 场景 | 触发 | 系统做什么 | 用户看到 |
| --- | --- | --- | --- |
| 买菜回来往里放 | 冰箱门打开，手拿食材穿过门口 | 认出每样食材，建库存批次，按类别估到期日，存一张证据图 | 关门 3 秒内首页出现"刚才放入：香蕉 ×3、鲜奶 ×1" |
| 拿出来吃或用掉 | 手拿食材从里往外穿过门口 | 找该食材最早到期的批次，扣减数量 | "刚才拿出：鸡蛋 ×2"，库存数同步减少 |
| 认错了 | 用户在手机上看到不对 | 撤销该条记录并回滚库存，或改数量、改名字 | 一键撤销，证据图留着可对照 |
| 日常查看 | 打开首页 | 汇总临期、库存、可做的菜 | "3 天内到期：鲜奶、豆腐"，推荐菜谱 |

## 3. 方案与系统架构

一个门口摄像头、一台主机、手机浏览器；主机上四步流水线把画面变成库存流水，其中过线判定是新做的核心，库存后端是现成的。

```text
门口摄像头（Moertek 2.4G 相机 → USB 接收器）
        │ 视频流
        ▼
主机：第一、二步 Mac，第三步 N100 迷你主机，一台机器跑完
  ┌─────────────┐   ┌─────────────┐   ┌─────────────┐   ┌─────────────┐
  │ 开门检测     │ → │ 检测 + 追踪  │ → │ 过线判定 ★   │ → │ 关键帧证据   │
  │ 画面亮度跳变 │   │ YOLO11n +   │   │ 穿过门口虚拟 │   │ 置信度最高   │
  │ 可选门磁兜底 │   │ ByteTrack   │   │ 线才记一次   │   │ 一帧裁图     │
  └─────────────┘   └─────────────┘   └──────┬──────┘   └──────┬──────┘
                                              │                 │（可选）
                                              ▼                 ▼
                       ┌────────────────────────────┐   ┌──────────────┐
                       │ 库存后端 smart_fridge_app    │   │ 大模型 API    │
                       │ FastAPI + SQLite，23 个测试   │   │ 只发物品小图  │
                       │ 商品 · 批次 · 流水 · 撤销 · 备份│   │ 返回名字/数量 │
                       └──────────────┬─────────────┘   └──────────────┘
                                      ▼
                       手机网页 · 家里局域网 :8000
                       刚才的变化 · 撤销 · 临期 · 库存 · 推荐
```

开门后每一帧都过检测和追踪，只有轨迹穿过虚拟线那一刻才产生一条事件，带着证据图写进库存后端；大模型只在开启时参与认名，不在主路径上。

**设计原则**

- 自动记账、事后撤销，而不是每次确认；
- 视频不落盘，只留过线关键帧做证据，数据全部留在家里；
- 小模型管动作，大模型（可选）管认名；
- 代码在 Mac 和 N100 上完全一致，换主机只是复制目录加两个服务单元。

## 4. 功能范围

本期只做"门口进出自动记账"闭环，识别真实到期日、扫码、多用户和云端全部不做。

**做**

1. 开门自动触发、关门自动结束一次记账会话（画面亮度跳变，可选门磁兜底）
2. 放入 / 拿出自动写库存流水，每条附证据图
3. 首页"刚才的变化"卡片，支持撤销、改数量、改名字
4. 按类别默认保质期，临期提醒
5. 库存清单、搜索、手动修正
6. 本地规则食谱；可选 DeepSeek 文本食谱（只发库存清单，不发图）
7. 一键备份包，用于从 Mac 迁到 N100

**不做（本期）**

- 条码、购物小票、包装日期 OCR
- 读包装上的真实到期日（纯视觉做不到，按类别估算）
- 多用户账号、公网访问、云同步
- 冰箱内部货架盘点（只看门口进出）
- 手持扫码枪硬件

## 5. 技术选型与对比

选型原则：先在 Mac 上验证再换硬件；小模型管"有东西过线"，大模型（可选）管"是什么、几个"。

**主机**：第一、二步用现有 Mac，第三步用 N100 迷你主机：这个任务只在开门的几十秒里跑小模型，CPU 就够，而且和 Mac 同一套代码。Jetson 两款只在需要 GPU 或本地视觉语言模型时才值得。

| 主机 | 推理能力 | 软件栈 | 价格（约） | 结论 |
| --- | --- | --- | --- | --- |
| N100 / N150 迷你主机（8 GB 内存，256 GB SSD） | CPU 跑 YOLO11n@416 约 15–25 fps | Ubuntu 24.04，和 Mac 完全同一套代码，内置 Wi-Fi | 约 600–900 元（估算） | **已选**：够用、最省事 |
| 旧笔记本 / 旧台式机 | CPU 跑 n 模型 10 fps 以上 | 同上 | 0 元 | 有就先用 |
| Orange Pi 4 Pro（旧项目已有） | CPU 约 8–12 fps，NPU 工具链不成熟 | ARM Linux，轮子偶有坑 | 0 元 | 在手可试，不够再换 |
| Jetson Nano 4GB（B01，老款） | GPU TensorRT FP16 @416 约 10–20 fps | JetPack 4.6，Python 3.6，只能走容器，无 Wi-Fi | 约 190–240 美元（[Yahboom](https://category.yahboom.net/products/jetson-nano-sub)） | 不推荐：已停产，软件老 |
| Jetson Orin Nano Super 8GB | 远超需求，可本地跑小视觉语言模型 | JetPack 6，直接 pip | 发布价 249 美元，2026 年 8 月有报道涨至 399 美元（[JetsonHacks](https://jetsonhacks.com/2026/08/26/jetsonhacks-august-2026-newsletter/amp/)，[DFRobot](https://www.dfrobot.com/product-2900.html)） | 只在要本地认名、不走 API 时值得 |
| Raspberry Pi 5 8GB | CPU 跑 n 模型 5–8 fps，需加 AI HAT | 常规 Linux | 约 600–800 元（估算） | 追踪帧率偏低，不推荐 |

**摄像头**：已选 Moertek 2.4G 无线款。

| 方案 | 延迟 | 安装 | 前提 | 结论 |
| --- | --- | --- | --- | --- |
| Moertek 2.4G 相机 + USB 接收器 | 100–300 ms | 相机贴冰箱，接收器插主机，不走路由器 | 接收器免驱 UVC；视角 ≥ 100°；相机能外接供电 | **已选**，实地测试方便 |
| 有线 USB 广角摄像头 | ≈ 0 | 一根 1.5 m 线到主机 | 主机在冰箱旁 | 备选，最稳最便宜 |
| Wi-Fi 网络摄像头（RTSP） | 0.5–2 s | 走家里路由器 | 必须支持 RTSP/ONVIF | 延迟对追踪不利，不推荐 |
| 手机当摄像头 | 0.3–1 s | 零成本 | iPhone 连续互通 / 安卓 IP Webcam | 只用于第一步临时测试 |

**模型与算法**

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 检测 | YOLO11n：自训 80 类食物权重 / COCO 通用权重；第四阶段用门口关键帧微调 | n 级模型 N100 的 CPU 跑得动 |
| 追踪 | ByteTrack（Ultralytics 内置） | 成熟，无需训练 |
| 过线判定 | 轨迹中心点穿过门口虚拟线，一条轨迹只记一次，存活 ≥ 3 帧才计 | 人流计数同一套方法 |
| 开门检测 | 画面平均亮度跳变（冰箱灯亮），可选门磁 | 不改冰箱 |
| 认名兜底（可选） | 多模态大模型 API，OpenAI 兼容接口，默认通义千问 | 只发裁剪后的物品小图 |
| 推理运行时 | Mac：PyTorch MPS；N100：ONNX Runtime / OpenVINO CPU，同一套 ultralytics 代码 | 各平台最快路径 |
| 后端 / 前端 | FastAPI + SQLite（已有，23 个测试）；原生 HTML/JS | 单机零运维，事务和备份已做好 |

## 7. 数据模型与接口

在现有后端上只加一张表和三个接口；库存批次、流水、媒体、备份全部复用。

**新表 `door_events`**（一条 = 一次过线）

| 字段 | 含义 |
| --- | --- |
| `id`、`session_id` | 事件 ID；同一次开关门共用一个会话 ID |
| `occurred_at` | 过线时间 |
| `action` | `in` 放入 / `out` 拿出 |
| `label`、`label_zh`、`confidence` | YOLO 类别、中文名、置信度 |
| `count` | 数量，默认 1，大模型或用户可改 |
| `vlm_json` | 大模型返回的名字 / 类别 / 数量（可空） |
| `media_id` | 关键帧在 `media_assets` 里的 ID（证据图） |
| `lot_id`、`inventory_event_id` | 生成的批次和流水，撤销时回滚用 |
| `status` | `applied` 已记账 / `undone` 已撤销 / `unmatched` 拿出但库存里没有该物 |

**接口**

| 方法与路径 | 做什么 |
| --- | --- |
| `POST /api/v1/door-events` | door_demo 上报一次过线（多部分表单：事件 JSON + 关键帧 JPEG）。放入 → 找或建商品、建批次、按类别算到期日、写 `receive`；拿出 → 找该商品最早到期的活动批次写 `consume`，没有则标 `unmatched` |
| `GET /api/v1/door-events?limit=20` | 首页"刚才的变化"卡片的数据，按会话分组 |
| `POST /api/v1/door-events/{id}/undo` | 撤销：放入的批次标 `discarded` 并写反向流水；拿出的数量加回并写 `adjust` 流水；事件标 `undone`。同一事务内完成，重复撤销返回已撤销 |
| `PATCH /api/v1/door-events/{id}` | 改名字或数量：先撤销再按新值重做 |

**默认保质期表**：一张 `category_shelf_life` 表（类别、默认天数、存放位置），先覆盖 80 类，按你家常买清单调整；入库时 `expires_on = 今天 + 默认天数`，用户可改。

**M1 · Mac 桌面闭环（3 天）**

1. 给终端开摄像头权限，香蕉 / 苹果 / 水瓶各过线 10 次，记结果（T2、T3）
2. 调线位置、置信度、轨迹存活帧数，把好用的参数写进 README
3. 可选：开通百炼 key，`--vlm` 跑通一次

**M2 · 无线摄像头实景，Mac 主机（7 天）**

1. 接收器插 Mac 找编号，相机贴冰箱顶前沿，画面中线对准门框
2. 开关门 20 次调亮度阈值，白天夜间各测一轮（T4）
3. 后端：`door_events` 表、上报接口、单测（到货前可提前做）
4. 后端：撤销接口、默认保质期表；`door_demo --post-url` 联调（T5、T6）
5. 前端：首页"刚才的变化"卡片、撤销按钮、隐藏拍照入口
6. 真冰箱连跑 3 天，每天核对一次，关键帧自动攒（T7）

**M3 · N100 独立主机（3 天）**

1. N100 装 Ubuntu 24.04，复制 `fridge_vision/` 和 `smart_fridge_app/`，用和 Mac 同一份 requirements 建环境
2. 接收器插 N100 验 UVC，跑 `door_demo` 测帧率，不足 10 fps 就把 imgsz 降到 320（T8）
3. 两个 systemd 服务开机自启，断电测试（T9）
4. Mac 备份包还原到 N100，手机核对库存（T10），Mac 退出

**M4 · 微调与准确率（4 天）**

1. 从关键帧里挑 200 张标注，类别按你家清单
2. 在 Mac 上微调 YOLO11n，导出新权重和 TensorRT 引擎
3. 多件、遮挡、快速进出调参（T12）
4. 20 种常买食材验收（T11）

**M5 · 两周真实使用（14 天）**

1. 开临期提醒、食谱、每日备份
2. 每天记纠错次数，第 7 天中期复盘，必要时补一轮微调
3. 第 14 天按 T13 结项

## 10. 风险与对策

最大的两个风险是手挡住小物件检测不到，和 80 类模型不认家里常买的东西；两者都靠第二步攒关键帧后微调解决。

| 风险 | 影响 | 可能性 | 对策 |
| --- | --- | --- | --- |
| 手握住小物件（鸡蛋、酱包），整条轨迹检测不到 | 漏记 | 高 | 微调加入手持样本；大模型兜底认名；提示放慢动作 |
| 80 类模型不含家里常买的东西 | 认错 | 高 | 按你家清单重定类别表，M4 微调 |
| 一次拿多件，轨迹互相干扰 | 漏记或重复 | 中 | 调 ByteTrack 参数；手机上快速改数量 |
| 门口强光或冰箱灯不亮，亮度触发失效 | 漏触发 | 中 | 门磁开关兜底 |
| Moertek 接收器不是免驱 UVC，或视角不够 | 第二步卡住 | 中 | 下单前核对；备选有线 USB 广角摄像头 |
| 2.4G 与家里 Wi-Fi 同频干扰 | 掉帧 | 中 | 接收器离路由器远一点；脚本已有自动重连 |
| N100 CPU 推理帧率不够（低于 10 fps） | 漏过线 | 中 | 分辨率降到 320 或换 OpenVINO；仍不够再换 Orin Nano |
| 摄像头位置不好固定、被碰歪 | 过线线位偏移 | 中 | 支架做牢；开机自检画面中线对准门框 |
| 隐私：关键帧发给大模型服务商 | 泄露厨房画面 | 低 | 默认不开 `--vlm`；只发裁剪后的物品小图 |

## 11. 隐私、数据与维护

所有视频和库存数据留在家里的主机上，默认不出网；只有开启大模型认名时，裁剪后的物品小图才会发给服务商。

- 视频不落盘，只保存过线那一帧的裁图作为证据；证据图保留 90 天后自动清理，库存流水永久保留。
- 网页只在家里局域网可访问，不开公网端口；在外面看用 Tailscale 一类内网穿透，不加公网登录。
- 密钥只走环境变量，不进仓库；现有 DeepSeek key 随压缩包流转过，上线前轮换。
- 每天凌晨自动生成备份包（数据库快照 + 引用的证据图 + SHA-256 清单），保留最近 7 份；每月在另一台机器还原一次验证。
- 关键帧训练集只在本地标注和训练；如用在线标注工具，先删掉有人脸的帧。
- 维护节奏：每周看一次纠错次数和 `unmatched` 条数，连续两周上升就安排一次微调。
