## 4. 方向对不对——我的判断

**对的地方**

1. **把交互压到零是对的产品直觉。** 上一版的"拍照、扫码、拍小票"每一个都是摩擦，家人不会配合。开门即记账是唯一可能被真的用起来的形态。
2. **先 Mac、再实景、再换硬件的顺序对。** 每一步都能单独验证，换硬件只是复制目录。砍掉 Jetson 是对的，它的旧软件栈本来会吃掉一周。
3. **保留 `smart_fridge_app` 做后端是对的。** 它的批次、流水、备份、事务边界已经做好，门事件只是多了一张表。重写会浪费一周。
4. **追手里的东西而不是盯货架，对现在的硬件和模型是对的。** 门口过线是人流计数级别的成熟方法，小模型跑得动。

**我担心的地方（按严重程度排）**

1. **"认出是什么"是这个方案的天花板，而且现在还没有真正测过。** 首轮只测了一个透明杯，模型叫它酒杯。COCO 模型只认 80 类日常物，你的自训模型是按商品照片训练的，对手里拿着、半遮挡、带包装袋的东西，准确率我估计一开始只有 40–60%。"有东西过线"会很准，"是什么"不会。
2. **"拿出"自动扣减会制造信任问题。** 牛奶每天拿出来倒一杯再放回去，按现在的逻辑是一次拿出（扣减）加一次放入（新批次），账会越记越乱。这是我写后端时就意识到、但按你"主要追放入"的要求先没处理的。
3. **"无感"是目标，不是现在的能力。** 现实版本是"放入自动、拿出半自动、纠错一键"。如果你和家人预期的是全自动，两周后会失望；如果预期的是"比手动省 80% 的事"，会满意。
4. **一个人同时拿两三样东西、塑料袋、叠在一起的盒子**，这套方法天然处理不了。它能处理的是"一次一件、让镜头看见"。
5. **Moertek 2.4G 没有验证过接收器是不是免驱 UVC**。如果不是，那它就是一个只能配自家软件的摄像头，我们用不了。有线款是必要的保险。

## 5. 我会怎么做（和现在计划的差别）

以下是我基于两天的观察，建议在现有基础上改的五处。都不大，但会明显改变使用体验。

**（1）放入自动，拿出改成"暂离"而不是立即扣减。**
拿出事件先把批次标成"暂离"；同一种东西 30 分钟内又放回来，就合并为一次"用了一点"（不建新批次，不扣整件，可选扣一个默认份量）；
2 小时没回来才真正扣减。这一条能消掉牛奶、酱料、水果盒这类高频进出的大部分噪音。后端改动约半天。

**（2）认名交给大模型，本地模型只负责"有东西过线"。**
你说过 API 也行。关键帧是一张 300×300 的裁图，发给通义千问或 Claude 这类多模态模型，一张不到几分钱，一天几十张可以忽略。
它认包装食品、品牌、数量的能力远超任何我们能训出来的小模型，而且不需要训练集。隐私上只发物品裁图，不发整个画面。
本地 YOLO 继续负责检测和追踪；认名用大模型；模型给的名字再反过来当训练标签，攒够了就能微调本地模型，以后再把 API 关掉。
这是投入最小、收益最大的一步，我建议第二步一开始就开。

**（3）纠错即标注。**
你在手机上每撤销或改名一次，就是一条人工标注。把这些自动存成训练样本，第三周微调时数据已经在那了，不用专门标注 200 张。
后端加一个导出命令就行。

**（4）手机页面以"刚才的变化"为中心，而不是库存清单。**
真正每天看的只有一个问题："它记对了吗？"所以首页第一屏应该是最近几次开门的记录、证据图、一键撤销或改名；库存和临期退到第二屏。
这是 M2 的 2.4，我建议做成最简单的样子：一张卡片、两个按钮，不要更多。

**（5）第二步末尾做一个 1 小时的实验：手部跟踪 + 大模型认名。**
用 YOLO11 的姿态模型跟踪手腕，手腕过线时裁手周围的区域发大模型。这个路线不需要检测器认识任何食物，对包装袋、盒子、不在 80 类里的东西
一视同仁。如果实验结果比"食物检测器 + 过线"好，第三步就换过去；代码上两条路线共用开门检测、过线、后端，只换中间一段。
我不确定它更好，所以叫实验，不叫计划。

**不建议现在做的**：冰箱内部货架快照对账（装内部相机、冷凝、光线都是新问题，第二阶段再说）、本地跑视觉语言模型（N100 跑不动，
Orin Nano 才行）、多用户和公网。
